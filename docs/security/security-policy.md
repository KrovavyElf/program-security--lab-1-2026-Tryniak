# Политика безопасности проекта CineVerse

## 1. Мета (Purpose)
Ця політика визначає обов'язкові правила, принципи та обмеження для забезпечення інформаційної безпеки програмного проєкту **CineVerse** (онлайн-кінотеатр) на всіх етапах його життєвого циклу — від розробки до експлуатації та супроводу[cite: 1].

## 2. Область дії (Scope)
Політика поширюється на:
- Вихідний код бекенду (.NET Core) та фронтенду (React).
- Сховища коду на GitHub (`KrovavyElf/program-security--lab-1-2026-Tryniak`).
- Базу даних (PostgreSQL) та середовище розгортання.
- Усіх учасників команди розробки.

## 3. Ролі та відповідальність (Roles and Responsibilities)
- **Розробник (Developer):** Звітність за безпечний код, відсутність хардкоду секретів, проведення попереднього рев'ю коду.
- **Адміністратор безпеки (Security Lead):** Перевірка моделі загроз STRIDE, контроль вразливостей та налаштування прав доступу.

## 4. Принципи безпеки (Security Principles)
- **Принцип найменших привілеїв (Least Privilege):** Користувачі та сервіси отримують лише мінімально необхідні права доступу.
- **Заборона зберігання секретів у коді:** Чутливі дані (рядки підключення до БД, JWT-секрети, API-ключі платіжних систем) зберігаються виключно у змінних середовища (`.env`).
- **Валідація вхідних даних:** Усі вхідні дані від користувачів проходять сувору серверну перевірку для запобігання SQL-ін'єкціям та XSS-атакам.
- **Безпечні паролі:** Зберігання паролів здійснюється виключно у вигляді хешів з використанням алгоритму `Argon2` або `BCrypt` із сіллю.

## 5. Безпечне середовище розробки (Secure Development Environment)
- Автентифікація в репозиторії виконується за допомогою захищених SSH-ключів (ED25519).
- Заборонено прямі коміти у гілку `master`/`main` без проходження перевірок.
