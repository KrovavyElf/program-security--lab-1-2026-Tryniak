# Модель загроз проєкту CineVerse (STRIDE)

## 1. Опис моделі порушника (Attractor/Threat Actor)
У межах проєкту CineVerse розглядаються такі типи порушників:
1. **Зовнішній неавтентифікований користувач (Гість):** Не має облікового запису, може переглядати загальний каталог фільмів, але намагається отримати несанкціонований доступ до адмін-панелі або чужих квитків.
2. **Легітимний користувач (Клієнт):** Авторизований користувач, який може намагатися маніпулювати запитами бронювання (наприклад, змінити ціну квитка або забронювати зайняте місце через race conditions).
3. **Зловмисник із локальним або мережевим доступом:** Перехоплює трафік або намагається здійснити DoS-атаку на API кінотеатру.

## 2. Аналіз загроз за методологією STRIDE
Методологія STRIDE використовується для систематичного виявлення загроз на основі діаграм потоків даних (DFD) проєкту[cite: 3, 4]:

| Компонент системи | Категорія STRIDE | Сценарій загрози | Захисний захід / Мітигація |
| :--- | :--- | :--- | :--- |
| **Модуль автентифікації (.NET API)** | **S**poofing (Підміна суб'єкта) | Зловмисник підробляє JWT-токен доступу, видаючи себе за іншого користувача або адміністратора. | Використання криптографічно стійкого підпису JWT (HMAC-SHA256) із коротким часом життя (Access Token) та безпечним зберіганням. |
| **Система бронювання місць** | **T**ampering (Зміна даних) | Зловмисник модифікує HTTP-запит на бронювання місця, змінюючи його статус або намагаючись придбати вже зайняте крісло за зниженою ціною. | Перевірка цілісності та валідація станів місць безпосередньо на бекенді з блокуванням рядків у PostgreSQL (Transactions / Pessimistic Locking). |
| **Логування операцій** | **R**epudiation (Заперечення дії) | Користувач заперечує факт купівлі квитка або здійснення транзакції через відсутність детальних аудит-логів. | Впровадження системного журналювання (Serilog) усіх критичних дій користувачів та транзакцій у захищені файли логів. |
| **База даних PostgreSQL** | **I**information Disclosure (Розкриття інформації) | Несанкціонований доступ до таблиць з персональними даними користувачів через SQL-ін'єкцію. | Використання Entity Framework Core з параметризованими запитами (захист від SQLi) та обмеження прав службового облікового запису БД. |
| **API бекенду** | **D**enial of Service (Порушення доступності) | Масована розсилка фейкових запитів на створення бронювання для виведення серверу з ладу. | Обмеження кількості запитів на рівні API (Rate Limiting) та валідація сесій. |
| **Адмін-панель** | **E**levation of Privilege (Підвищення привілеїв) | Звичайний користувач намагається отримати доступ до ендпоїнтів керування розкладом фільмів та касою. | Реалізація суворої рольової моделі (RBAC - Role-Based Access Control) на бекенді за допомогою ASP.NET Core Policies. |
